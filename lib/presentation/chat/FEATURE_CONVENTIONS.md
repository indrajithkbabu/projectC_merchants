# Chat Feature Conventions

WhatsApp-style Message inbox, plus visitor enquiry entry. On another store's product photo, a tap opens a composer (no suggestion chips); send writes one discussion for that photo, lists the store on Message, and opens the thread. Store-page long-press and the enquiry basket are unchanged.

## Mandatory Update Rule
- If chat screens, composer rules, or the shell entry change, update this file in the same change.

## UI Rules
- The second shell tab is **Message** for every account (chat icon, unread count). The title is the active profile name with the profile switcher. It lists chats only. Search plus filters All / Unread / Customers / Stores, aligned to the left. The green new-chat button sits at the bottom right and opens New chat (New group, Find stores, Invite friends, then Stores and Followers). An empty chat stays off the list until the first message.
- One discussion opens the thread directly. Two or more open the discussion list: search, a Closed row, long-press to mark read or close, drag to reorder open rows. Reopen moves a discussion to the top. A discussion can have no product; its name is the date, and a second unnamed one the same day adds the time.
- On another store's catalogue, the header **chat** bubble opens that store's thread. Long-press selects photos (green check, `N selected`). **Ask about N** opens the enquiry basket. Send writes one message and one discussion per photo, then opens the thread. Those store chats appear on Message.
- The thread is a pushed route (`chat_thread_route`). The shell nav stays on the list only. A product discussion pins the product under the header. The composer is a paperclip, a lock for team-only notes, the field, and send. The paperclip slides a tray up under the composer with smaller Gallery, Camera, Catalogue, and Document buttons, and the newest photos underneath. Scroll that grid and tap photos to select them, then send. Tapping the message field closes the tray. Team notes are amber `#E3B54E` and hidden from other stores. Swipe a message right to reply. The quote name and bar are green, and a photo reply shows a small image. Long-press a message highlights that row and opens Reply, Reply to team, Copy, and Star from the top-right menu. A photo fills its bubble and the time sits on the picture. Tap the photo to open it full screen; pinch or double-tap to zoom. `@Name` is blue `#3B9BE8` and leaves an @ on the row until that discussion is opened.
- Profile (tap the name) is mute, phone, and members grouped by store. Mute has no expiry. Muted chats still show unread and @, plus a slashed bell.
- Use `AppTextStyles`, `AppColors`, and `AppPadding`. A thread header is the discussion name over `Store · N people`. Incoming bubbles stay graphite. Your messages are white with black text. Names appear inside the bubble, and only in a group. Team notes use a dashed amber outline. Read ticks and @mentions use `#3B9BE8`.
- Lists leave `FloatingBottomNavBar.reservedHeight` inside the scroll view.
- Unread is a count. No "needs reply" label.

## Logic Ownership
- The Message list reads `ChatRepository`: `GET /chat/capabilities`, then `GET /chat/relationships?view=inbox` for the active profile. Search and All / Unread / Stores filter loaded rows. Groups has no phase-1 data. A personal profile lists store chats only. `writesEnabled: false` or `enabled: false` leaves the list readable or shows chat unavailable, and disables new chat.
- The store-page chat bubble and a store row in New chat call `openStoreChat` (`POST /chat/relationships` with `targetStoreId`) and open the existing thread. A follower row uses `customerPhone` on the same call. The first text in an empty thread, and the first text after + starts a new discussion, calls `POST /chat/relationships/:id/discussions`. A local draft id is never sent as a discussion id. Reply on another store's product calls `sendFirstMessageToStore` (`POST /chat/relationships`, then `POST .../discussions` with the text and product id), refreshes the Message list, and opens that thread with the product photo on the discussion card. The chat snapshot has no image, so the photo comes from the product that was open, then from `GET /products/:id` when the thread is opened later. Tapping an API row opens the same thread screen. Public text sends with `POST .../messages`. A photo uploads with `POST .../photos`, then the message sends `photoIds`. A photo larger than `photoBytes` (8 MB) is compressed to JPEG before that upload. Opening the thread posts `POST .../receipt` with `state: read` for the newest incoming message. While the thread stays open, that discussion is reloaded every few seconds so a new message and read ticks appear without leaving the screen. The Message list reloads about every 8 seconds. Live socket is not connected yet. The lock still writes a team note only on this device: Phase 1 has `notes: false`, so that note is not posted. The header, lock, and attachment controls stay as they are. New chat still uses `ChatMockStore`.
- `ChatMockStore` holds threads, quick replies, and auto-reply text in memory.
- `ChatTab` copies the signed-in name, store name, and own-store catalogue into that store during build. It does not notify from that sync. Accounts without a store do not read `StoreProfileBloc`.
- An empty chat started from New chat stays off the list until the first message.
- Sending follows the open discussion. Sharing a product while a discussion is targeted attaches it inside that discussion. The lock sends a team-only note (`writerStore` is this store).
- The thread shows one discussion at a time. Other discussions stay on the discussion list.
- Opening a discussion marks it read and clears its @. Closed discussions are not selectable.
- Find stores reuses `ContactsTab(showBack: true)` with the shell contacts and listing blocs. Invite friends reuses `invite_friends_route`.
- Replace `ChatMockStore` when the API exists. Keep the screens on the same thread, discussion, and message shapes until the contract is known.
